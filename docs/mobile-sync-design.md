# スマホ連動（モバイル同期）— 要件定義と設計

開発用途。`feature/mobile-sync` ブランチで実装（本体 main / 他featureには触れない）。

## 1. 目的・ユースケース
- Mac（デスクトップ／Webアプリ）で編集した時間割・指導計画が、**スマホを開くと最新の状態で出てくる**。
- まずは「**閲覧＝確実に最新**」を最優先（今日の時間割・変更・指導計画をスマホで見る）。編集の双方向同期はその次。
- 想定端末: Mac（編集主）＋ iPhone（閲覧主、PWAとしてホーム画面に追加済み）。単一ユーザー・単一データ。

## 2. 現状（重要）
同期の“基盤自体”はすでにある。無いのは「摩擦の少ない経路」。
- **Google Drive `appDataFolder` 自動同期が実装済み**（`lib/googleDrive.ts` / `GoogleDriveContext.tsx`）。アップロード／ダウンロード／**競合検知(`conflict`)**／世代管理あり。
- **PWA 化済み**（`manifest.json` + `sw.js`：Network First + オフラインキャッシュ、インストールバナー）。
- データ単位は **1つの `TimetableFile`（JSON）**。全学期・base・ops・指導計画を内包。`meta.updatedAt` を全変更で更新。

### なぜ「スマホで連動しない」のか（仮説）
- モバイルの **Google OAuth（GIS/gapi）は摩擦が大きい**：PWA/Safari でのトークン取得・再ログイン・ポップアップ制限。
- Drive 同期は**明示操作寄り**で、スマホ側の「起動＝自動プル」が弱い可能性。
- → **トークン1本で叩ける専用同期バックエンド**があれば、モバイルの体験は大きく改善する（ユーザー方針＝Vercel or 自宅サーバー）。

## 3. 要件

### 機能要件
- F1. デスクトップで保存すると、**スナップショット（TimetableFile全体）をサーバへ push**。
- F2. スマホでアプリを開くと、**サーバから最新を pull** して表示（起動時＋フォアグラウンド復帰時＋任意で定期）。
- F3. どちらが新しいかは `meta.updatedAt`（＋サーバ採番の版番号）で判定。**単一ユーザー前提で last-write-wins**、ただし「サーバの方が新しい」時は取り込み確認 or 自動取り込み（設定）。
- F4. 既存の Drive 同期と**排他ではなく共存**（同期先を「なし／Drive／自前サーバ」から選択）。

### 非機能要件（この人の価値観に直結）
- **N1. プライバシー最優先**：時間割は担任モードで児童関連の記述（教科・単元・各コマのnotes・クラス別上書き）を含みうる。**第三者クラウドに平文で置かない**。
- N2. どこからでも届く（学校・自宅の両方から iPhone で見られる）。
- N3. 低運用（個人利用。常時メンテ不要）。
- N4. オフライン耐性（電波が無くても直近のキャッシュは見られる＝PWA既存挙動を維持）。
- N5. 取り返しのつく設計（サーバ側は版を保持し、誤上書きから戻せる）。

## 4. アーキテクチャ選択肢

| | A. Vercel（サーバレス＋KV/Blob） | B. 自宅サーバ（既存expressを常駐）＋トンネル | (C. Drive同期の改善のみ) |
|---|---|---|---|
| 届きやすさ(N2) | ◎ どこからでも | ○ Tailscale/Cloudflare Tunnelで可 | ○（Google経由） |
| プライバシー(N1) | △ 米国クラウド。**E2E暗号化必須** | ◎ データが自宅に留まる | △ Googleに預ける |
| 運用(N3) | ◎ ほぼゼロ運用・無料枠 | △ Mac mini常時起動・トンネル設定 | ◎ 追加ゼロ |
| 実装コスト | ○ ストレージアダプタ＋関数 | ○ 既存express流用が効く | ◎ 小改修 |
| ユーザー方針 | 候補 | 候補（Mac mini あり） | 今回は対象外 |

### 推奨：ホスト非依存コア ＋ **E2E暗号化** ＋ どちらにもデプロイ可
- **同期コアを移植可能に作る**：`SyncStore` インターフェース（`get/put/listVersions`）を、
  - 自宅サーバ = ファイルシステム実装、
  - Vercel = KV/Blob実装、
  で差し替え。**アプリ側・APIの契約は同一**。ホスト選択は“デプロイの選択”に格下げできる。
- **E2E暗号化を既定**：端末側で AES-GCM 暗号化した blob だけをサーバに置く（鍵＝ユーザーが設定する合言葉から PBKDF2 派生、端末間で同じ合言葉）。
  - → **サーバは中身を読めない**。Vercelでもプライバシー要件(N1)を満たす。自宅サーバなら二重に安全。
- これにより「Vercel か 自宅か」は**後から変えられる**。まず動くものを作り、置き場所は運用しながら選べる。

## 5. 同期プロトコル（MVP）
- 認証：`Sync-Token`（十分に長いランダム文字列。端末に保存）。E2E鍵とは別。
- エンドポイント（`/api/sync`）:
  - `GET  /api/sync/snapshot` → `{ version, updatedAt, ciphertext, iv }`（無ければ204）
  - `PUT  /api/sync/snapshot` ← `{ updatedAt, ciphertext, iv, baseVersion }` → `{ version }`（`baseVersion`不一致なら409で競合返却）
  - `GET  /api/sync/health`
- 版管理：`put` ごとに `version` を単調増加。直近N版を保持（誤上書きから復旧＝N5）。
- クライアント：
  - 保存時：暗号化して debounce push（`baseVersion` 添付）。409なら「サーバが新しい→取り込むか上書きか」を提示。
  - 起動／復帰時：`GET snapshot` → 復号 → `meta.updatedAt` がローカルより新しければ取り込み。
- **プライバシー**：サーバに出るのは ciphertext と `updatedAt`（時刻のみ）と版番号だけ。児童名・教科・notesは平文で出ない。

## 6. MVP スコープ / 段階
1. **P1（この設計の実装本体）**：ホスト非依存の `/api/sync`（express＝自宅サーバ即動作）＋ `SyncStore` ファイル実装＋E2Eクライアント＋起動時プル。まず「Macで保存→iPhoneで開くと最新」。
2. **P2**：Vercelアダプタ（KV/Blob）＋デプロイ手順。置き場所を選べるように。
3. **P3**：競合UI（409時の取り込み/上書き）、定期プル、同期状態インジケータ。
4. 既存Drive同期は残す（同期先セレクタで択一）。

## 6.5 使い方（P1・自宅サーバ運用）
実装済み。エンドポイント `/api/sync`（dev=Vite / 本番=express の両方で動作）。

1. **サーバを起動**（Mac mini 等・自宅サーバ）
   ```bash
   npm run build && npm start      # 本番(express, :3000)  ／ 開発なら npm run dev
   ```
   初回に同期トークンが `.sync-data/token.txt` に自動生成される（`SYNC_TOKEN` 環境変数で固定も可）。
2. **Mac（サーバ同居）**: サイドバー「スマホ連動」→「このMacから」でトークン自動設定→「同期を有効にする」。
   以後、保存すると自動送信。
3. **iPhone**: 同じ URL をSafariでPWA追加。「スマホ連動」で **サーバURL**（例 `http://mac-mini:3000` や Tailscale の `http://100.x.x.x:3000`）と、Macで表示された**トークン**を入力→有効化。開くと最新が入る。
4. **外から届かせる**（学校からiPhoneで見る）: **Tailscale** 推奨（Mac miniとiPhoneを同一 tailnet に入れるだけ。ポート開放不要・経路は暗号化）。または Cloudflare Tunnel。

- データは `.sync-data/`（gitignore）。直近30版を保持し `GET /api/sync/versions` で確認可（誤上書き復旧用）。
- 認証はトークン（`x-sync-token`）。漏洩時は `.sync-data/token.txt` を消して再生成（各端末で入れ直し）。

## 6.6 Vercel 化（P2・後日）
`SyncStore` を Vercel KV/Blob 実装に差し替え、`/api/sync` を Vercel Functions として配置するだけ。
アプリ側（`timetableSync.ts` / `SyncContext`）は無改修。**その際は E2E暗号化を有効化**して児童データを平文で置かないこと（設計 §4）。

## 7. リスクと対処
- 鍵紛失＝復号不能：合言葉は端末に保存＋復旧用にエクスポート導線。サーバ版は無意味化するだけでローカルファイルは無傷。
- トークン漏洩：漏れても中身はE2Eで読めない。トークンは再発行可能に。
- 自宅サーバ選択時の到達性：Tailscale（推奨・簡単）or Cloudflare Tunnel を手順化。
